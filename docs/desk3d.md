# desk3d

A 2D board with depth (4 November 2026, Korbi: "ensure that it has an extremely pretty 3D mode, even if it's a 2D projection when more appropriate"). For DOM games where true 3D would get in the way of reading and typing: the board becomes a slab of oak with a bevelled edge on a leather desk, lit by a window and a lamp, that tips a little with the phone (or the pointer) and dips under a tap. `desk3d.js` + `desk3d.css`; Nonet is the first user (`docs/sudoku.md`). Pure CSS 3D: the board stays the page's own DOM.

**Adopting it, about 12 lines.**
1. Markup: the board's stage is a `.fit-box` with the board's host inside it (`<section id="stage" class="… fit-box"><div id="board"></div></section>`). Link `desk3d.css` after the game's board stylesheet and before its own and `themes.css`.
2. Script, once the markup exists:
   ```js
   import { desk3d, deskView } from "./desk3d.js";
   const choice = deskView("mygame"), desk = desk3d($("stage"), $("board"));
   const show = () => desk.set(choice.get() === "desk");
   show(); choice.watch(show);           // the default is mode3d.js's (battery saver: flat); Settings' 2D mode is followed live
   ```
   and in the menu's settings part `choice("View", choice.options, choice.get(), v => { choice.set(v); show(); })`. The choice is written only when the player picks (`suite:<game>-view`, the device's own).
3. CSS: `--d3-bleed: 1rem` on the stage runs the blotter to the screen's edges on a phone (the app's side padding), `--d3-r` rounds it; set both back to `0px`/a radius under the sideways query (see `sudoku.css`).
4. For a digit grid (`digits.js`: Calcudoku, Tally) that is all: `desk3d.css` already dresses `.dg`, its keys and its tools. Any other board needs its own rules under `.d3-on` (below). `d3.glint()` sweeps light over the slab (call it once on a solve).

**What it does to the page.** `desk3d.js` wraps the host in `.d3-world` (a `display: contents` box while flat), adds the leather plane, and dresses the host's first child, the slab, with a frame, four sides, a cast shadow and a sheen (re-dressed whenever the game replaces its board). `d3-on` is put on the page's root (`#app`) while the desk shows: every rule in `desk3d.css` hangs on it, so with it off the page is exactly as it was, and the game's own pad can be styled `.d3-on .thing`. The world's tilt is the only thing that moves: one `transform`, eased in a rAF that stops when it settles (no idle frames).

**Traps.**
- **Hit-testing.** CSS transforms keep it true (`elementFromPoint` and taps follow the projected cells), provided nothing in the 3D group is a hit target but the slab: the desk, shadow, sides and sheen are `pointer-events: none`. Checked on Nonet by projecting every cell's quad (`DOM.getContentQuads`) and probing the centre and the four corners, at rest and with the pointer in both corners, at 390x664, 390x600, 820x1180 and 1180x820: 4860 probes, none off.
- **The stage must not be `overflow: hidden`.** The tilted desk overflows it and a hidden box can still be scrolled (a focus or `scrollIntoView` moved the whole stage once); the kit uses `overflow: clip`.
- **Text stays DOM text.** Never rasterise (`html2canvas`, canvas) and keep the board's own layers flat: only the slab's frame, sides and desk are in 3D, the cells are not (81 3D layers would cost a phone and blur). The tilt is 17 degrees at rest; text is resampled by the compositor but stays sharp at 2-3x.
- **Perf: composited transforms only.** Anything that changes per frame must be a `transform` or `opacity` of its own layer. A background image on the moving plane was repainted on every frame (a tiled image as a second `background` of the desk: 17 full repaints in 2.5 s); the grain is now `.d3-desk::after`, its own layer, and a pointer sweep paints nothing. Do not add a `filter`, a `mix-blend-mode` or a blur to anything in the world; `will-change: transform` is set on the world's layers to lock their raster scale. Cost measured on Nonet at 390 px: about 1 ms of main thread per frame (one style recalculation of the board's 85 elements, script under 0.1 ms), no layout, no paint.
- **Motion is off** under `prefers-reduced-motion` (the tilt rests, the press and the tile drop don't animate, the glint becomes a fade) and under battery saver (`deskView().get()` is flat: the page is today's). Device tilt needs no permission on Android; on iOS it needs a prompt, which the kit never opens unless `{ askMotion: true }` (a system dialog at the first tap): an iPhone gets the rest tilt, the press and the pointer (iPad with a mouse or pen).
- **Class names.** `themes.css` restyles by pattern: Kontor `[class*="-go"]`, Office `[class*="-label"]`, `-tag`, `-cat`, `-chip`, `-note` (`.dg-tags` is already caught by Office's). Never name a desk class with those syllables (`d3-gold`, `d3-tag`, `d3-chip`: `-go` is in `-gold`). Kontor and Modern are gone (4 November); the kit's looks are Codex, day and night, and Office at night, as token blocks at the top of `desk3d.css`. A new look is one more block of `--d3-*` tokens, nothing else.
- **Specificity.** Digit-grid rules start `:root .d3-on …` to outrank `themes.css`'s `html:is([data-theme…]) .dg`. The cell's ring and glow go through `--d3-ring` (`box-shadow: var(--d3-ring, …), the recess`), so a state sets the variable rather than the shadow and does not undo another's.
- **Layout.** The stage's padding is the desk's margin: the slab is as large as the stage's content box allows, so the desk costs a board about 5% of its width at 390 px. Nothing in it changes size once drawn; a stage that is `display: grid; place-items: start` in flat is centred while the desk shows.

**Next adopters** (Calcudoku, Tally, Cull: the digit grid, nothing more; Crossword, Acrostic, Crates, Punt, Crates' crates): a board that is not `.dg` needs, under `.d3-on`, its own cell wells, raised tiles (reuse `--d3-tile-*`, `--d3-key-*`), lit highlights (`--d3-peer`, `--d3-spot`, `--d3-dim`) and oxblood errors (`--d3-ox*`); take Nonet's rules in `desk3d.css` as the model and keep each game's rules beside the kit's, not in it. Crossword and Acrostic are dense: use a lower tilt (`REST_X` in `desk3d.js` is a constant; make it an option first). Crates' tiles want real thickness: the host's first child is the slab, so a 4x4 of crate tiles can sit in one. A page whose pad is outside the stage (every Nonet-like) styles it `.d3-on .its-key`.
