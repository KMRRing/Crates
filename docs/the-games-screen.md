# The games screen
The app is Codex, and it opens here: the site's front page (`index.html`, `home.js`) is the screen of games with no game open and nothing to close back to. Every game is a page of its own; Crates, which used to be the front page, is at `crates.html`, and a link made for it back then (a shared board, a room, a run, a pool: `?b=`, `?room=`, `?run=`, `?cat=`) is forwarded there. A link carrying codes (`?solo=`, `?duo=`) stays home and takes them on.

Over it, the mark as the C of CODEX (Office: the name alone) on the same graduated rule as a game's header. Under that, the head is one line: A one-person icon with your **solo** code (8 letters: every device with it is in the same state in every game), a two-person icon with your **partner** code (4 letters), then what your partner is playing (tap it for the partner sheet); on the right Settings (a gear in Codex, a pair of sliders in the other themes), a refresh icon (load the newest version; it turns while it fetches) and an ×. Tapping a code copies this page's link with it: the solo link carries both codes (open it on another of your devices and it follows your games and your partner), the partner link only the partner code (your partner opens it and you're linked). Holding a code (or tapping one that isn't set) lets you type one: a code that already holds games or a pair is followed or joined, what's there winning; a code nobody has yet starts fresh, from what this device has now (a new partner code is an empty room), so you can pick your own, any letters (codes the app makes avoid I and O). Solo sync: each game's saved state, the review pile and your settings go up to Firebase a moment after they change (every change carries its time) and come down when a page opens or comes back into view, the newer winning key by key; a change from elsewhere to the game you have open reloads it once. Crates' run follows the same code through its own sync. `suite.js` does all of this, loaded on every page through `pwa.js`; the store lives under `crates/runs/` at the solo code moved on seven letters, so the database rules need no change. Under the head, before the tiles, Random: a game at random from those you choose, and the next when its round is over (README, Random mode).

The tiles, in sections under small headings in the one list (October 2026, when the games passed forty: a phone showed fifteen at a time, and finding one meant scrolling past most of the rest): **Knowledge**, Crates, Punt, Quote, Origin, Order, Chart, Nexus, Crossword, Lode, Isomer, Acrostic and Nonogram, then Almanac (the lookup of everything the games know; Lexicon until 2 November 2026, its id still `lexicon`) and Ledger (the record of how you learn): the games that draw on the knowledge base and bank what you miss (2 November 2026, Korbi, after the library review: Lode, Isomer, Acrostic and Nonogram go to Knowledge, and "move lexicon and ledger to knowledge"; Deck, which reviews those misses, has no tile since 31 October 2026, Korbi: "remove deck tile": the banner's Deck choice opens it, and `apps.js` still lists its page for its name and logo, as it does Chess's puzzle rush); **Courses**, Calibre and Parley, each a subject taught in order, with levels, chapters or a syllabus of its own (31 October 2026, Korbi: "let's separate "knowledge" from "courses""); **Puzzles**, Slate, Delta, Spot, Manifest, Pipes, Survey, Stow and Slipway (a 3D carving puzzle: from Idle on 4 November 2026, the split review: Idle is "no puzzle to work out"); then Classics, Idle (which has Harbour since 3 November 2026, Korbi: "Harbour should go to idle", Courier, the swipe runner, and Loose cargo, Stow's Block Blast game with a tile of its own, since 4 November) **Board games** (boards, Mahjong, Dominoes, Rack, Hanse) and **Cards & dice** (tricks, climbing, rummy, Solitaire, Liar's dice, Cartel), split from one "Board & card games" section of 22 on 4 November 2026, as `SECTIONS` in `apps.js` lists them; **Party**, Party itself, then each of its games with a tile of its own (Undercover, Who am I?, Echo, Decoy, Gauge and Fuse: each opens Party on that game, the page wearing its name and logo), Cue and Company; and the **Appendix** at the back (README, The Appendix), what is set aside until it leaves for an app of its own or goes: the six casino games ("move all the casino games to the appendix", 2 November 2026), Blend, Refinery, Guilloché, Timegrapher, Banquet (4 November 2026) and a placeholder for the fuels version of Speed maths. Every game is in one section only (`sec` in `APPS`, `SECTIONS` in `apps.js`), so there's one place to look for it. They are headings in the one list, not tabs: a tab hides games behind a tap, as the "…" tile did until October 2026, when the eleven from Arb to Cue sat behind it in a popup with Settings (Settings is in the head now). Three across on a phone, four on an upright tablet, six on a screen held sideways. The screen itself never scrolls; the tiles do, in their own box under the head: on a phone a tile is 5.5rem high, so its logo and name keep their size, and on a tablet 5.4rem (they once shared a tablet's height so every game fitted it, which forty-odd games no longer can). The box's edge fades out where there are more tiles past it, top or bottom (`apps.js` marks which as it scrolls). Opening the screen from a game brings that game's tile into view, however far down the list it is.

Favourites, search and filter (3 November 2026, Korbi: "allow user to favourite games" and "also allow the user to search for games (search appears when the user screen is already located at the very top of the menu and then the user scrolls up. filter and search appear, and when scroll is let go, they don't disappear unless the user scrolls down (if the user isn't at the very top when they start the up scroll, it also doesn't appear). filter can be used to select a category or do it by player count)"; the same day, of the first version, which put a starred game at the head of its own section: "Favouriting shouldn't just go to the front of the section there should appear a section 'favourites' at the top of the menu with it in it"). A star in each tile's corner (`games-bar.js`, the rules in `games-find.js`) moves a game into **Favourites**, a section above Knowledge that exists only while a game is starred (nothing starred, the screen is as it was). Its games are in the screen's order, the sections and then each section's own, and a starred game is shown there only, not also in its own section; the star comes off and it goes home. Trap: a filter by section still means a game's home section, so a starred Punt shows in Favourites when Knowledge is chosen, and a filter or search never hides a starred game that matches it. Pull the list down from its very top (a drag, or the wheel up) and a search field and two filters, a section and a number of players, come down above it; they stay when you let go and go away when you scroll down. Traps: a pull counts only if the list was at the very top when the gesture began and stayed there, and a wheel gesture is the events within 150 ms of each other, so a flick that began lower and arrives at the top does not bring the bar down; an iPhone bounces past the top (scrollTop below zero, and no scroll event for the pull), which is why the touch events are read, and that bounce has only been tried in Chromium. The bar sits above the list's scroller, not in its content: Safari has no scroll anchoring, so a bar in the content that collapsed while you were lower down would jump the tiles. A search or filter in force keeps the bar when you scroll down (it would leave a list with games missing and nothing saying why); closing the screen forgets both. A star is one key a game, `home:fav:<id>`, so two devices starring different games merge, key by key; a key for a game that has gone is read by nothing. `players` in `apps.js` is [fewest, most] people who can play (1 is one alone, against the computer or a solo puzzle), and `tests/games-find.mjs` fails when it disagrees with `party-core.js`, `DUO_GAMES` or the seats a table has: a game that gains a party table or a duo match changes its entry.

Settings (at the top right, beside refresh) holds the theme, day or night, a switch for the banner under the head, Deck, Random and Choose (below, and README, Deck, "Scope"; on at first, this device's own: `suite:banner`, which never syncs, and it applies at once, nothing reloads), the pictures kept offline and, folded away, Start a game over (October 2026): tap a game, confirm, and every key it keeps goes (its levels, stars, saves and settings: Calibre's designs and progress, Harbour's campaign, a run under way), on this device and on every other with your solo code. A removal syncs like any change, carrying its time, so an older copy on another device can't bring the game back, and keys that only another device had are taken from the code and removed there too (offline, this device's go at once and their removals go up when it's back). The game open in the page starts again at once; until the page reloads nothing of the reset game can be written again, so a page still showing it can't save it back (`resetGame` in `suite.js`). Not listed: Crates, whose run is synced on its own and which resets its learning in its own Settings; Deck, whose pile is every game's misses; Ledger and Almanac, the records of the others; and the Appendix (3 November 2026, Korbi: it stays out of Random and of this). A game's keys are its own prefix, and the other names some keep: Slate's `glyph:` and `slate:`, Blend's `blend:` and `blend2:`.
**2D mode (battery saver)** (4 November 2026, Korbi: "add a setting in main menu settings: '2D mode (battery saver)'. this does the default across all games - user's choices for specific app preferences (3d vs 2d) are still remembered"): `settings:flat`, this device's own (in `suite.js`'s `LOCAL`), `mode3d.js`. A game with a 2D/3D choice keeps it under its own key and writes it ONLY when the player picks one; with none stored it asks `defaultIs3D()` / `wants3D()`. Never write the default (or a failure to start 3D) into that key, or the setting stops reaching the game. `tests/flat-mode.mjs` fails for a file that draws in WebGL and is not reached from a page that asks. Mines' solids, Pipes' cube and Stow's decks are different boards, not views, so they ignore it.

In a game's header the logo is 40 pixels, as large as the rete opposite it.

On an upright tablet the screen keeps four tiles across (six made them tall and thin, their names cut) and sideways six, the whole width; on a tablet the logos and names grow into the bigger tiles (README, Bigger screens).
